# Product Requirements Document - Teaching Manage 系统完善

**Author:** Prola
**Date:** 2026-02-18
**Version:** 1.0

## 1. 执行摘要

### 产品愿景

Teaching Manage 是面向 IT 编程培训机构的教学管理平台。本次系统完善旨在修复现有阻断性问题，使系统达到生产就绪状态。

### 核心目标

- 修复 4 个已知的阻断性问题（Dashboard 404、学科详情、评分 500）
- 实现 UI 一致性（全局主题统一）
- 确保三种角色（管理员/教员/学员）核心流程可用

### 项目范围

| 阶段 | 内容 |
|------|------|
| **Phase 1 (MVP)** | 修复阻断性错误 |
| **Phase 2 (Growth)** | UI 一致性与体验优化 |
| **Phase 3 (Vision)** | 暂不纳入 |

### 成功定义

系统可投入 30-100 人规模的实际培训使用，无 500/404 错误，所有页面应用统一主题。

## 2. 项目背景

Teaching Manage 支持：
- 3-5 个并行学科的教学管理
- 30-100 名学员的管理
- 完整的作业提交、评审、评分流程
- 分组学科的小组协作管理

**技术栈：**
- 后端：Spring Boot 3.2.2, MyBatis-Plus, SQLite, JWT, Java 17
- 前端：Vue 3, Vite, TypeScript, Element Plus, Monaco Editor, Pinia

## 3. 项目分类

| 维度 | 分类 |
|------|------|
| 项目类型 | Web App (SPA + REST API) |
| 领域 | EdTech（教育科技） |
| 复杂度 | 中等 |
| 项目上下文 | 棕地（Brownfield）- 系统完善 |

| 问题 | 影响范围 | 优先级 |
|------|----------|--------|
| Dashboard 404 错误 | 所有用户首次登录体验 | P0 |
| 学科详情无法显示 | 学员核心旅程 | P0 |

## 6. 产品范围与阶段规划

### Phase 1: MVP - 阻断性问题修复

**必须完成（P0）：**

| 任务 | 影响范围 | 验收标准 |
|------|----------|----------|
| 修复 Dashboard 404 | 所有用户 | 登录后 Dashboard 正常加载 |
| 修复学科详情无法显示 | 学员 | 点击学科显示完整详情 |
| 修复评分功能 500 错误 | 教员 | 评分保存成功，无错误 |
| 端到端流程验证 | 所有角色 | 三种角色核心流程通过 |

### Phase 2: Growth - UI 一致性与体验优化

**应该完成（P1）：**

| 任务 | 说明 |
|------|------|
| 全局主题变量定义 | 统一颜色、间距、字体变量 |
| 页面 UI 一致性检查 | 所有页面应用全局主题 |
| 统一错误提示组件 | 用户友好的错误反馈 |
| 加载状态标准化 | 异步操作显示加载指示 |
| 表单验证一致性 | 前后端验证规则统一 |

### Phase 3: Vision - 未来扩展（不在本次范围）

**暂缓项目：**
- 开发者教育特性（代码协作增强）
- 系统扩展性改造
- 新功能开发

### 风险缓解策略

| 风险类型 | 风险描述 | 缓解措施 |
|----------|----------|----------|
| 技术风险 | 错误根因复杂 | 逐步调试，保留回滚能力 |
| 技术风险 | 前后端联调 | 浏览器开发工具追踪 |
| 资源风险 | 时间不足 | 优先 P0，P1 可分批 |

### 依赖关系

Phase 1 的阻断性问题必须在 Phase 2 UI 优化之前完成。

## 7. 用户旅程

### 旅程 1：学员 - 查看课程并提交作业（核心旅程）

**人物：小李** - IT 培训学员，正在学习 Java 基础

**当前痛点：**
- 🔴 登录后 Dashboard 404，不知道有什么课程
- 🔴 点击学科后看不到详情，无法了解课程安排

**理想旅程：**
1. **登录系统** → Dashboard 加载，显示今日课程、待提交作业、未读通知
2. **进入学科** → 点击学科，看到课程日历和列表
3. **查看课程详情** → 课程内容、作业要求、截止时间清晰展示
4. **提交作业** → 上传文件，显示进度，确认成功
5. **收到反馈** → 通知提醒，查看评分和评语

**成功时刻：** 小李顺利完成了第一次作业提交，对系统产生信任感。

### 旅程 2：教员 - 评审作业并评分（核心旅程）

**人物：张老师** - Java 课程教员，需要批量评审 30 名学员的作业

**当前痛点：**
- 🔴 评分功能 500 错误，无法完成评分
- 🟡 界面风格不统一，操作不够流畅

**理想旅程：**
1. **登录系统** → Dashboard 显示待评审作业数量
2. **进入课程** → 查看学员提交列表和状态
3. **查看提交** → 文件树展示，代码高亮
4. **添加评论** → 行级评论即时保存
5. **完成评分** → 选择等级，添加评语，**保存成功** ✅
6. **批量处理** → 快捷操作，通知自动发送

**成功时刻：** 张老师高效完成了全班作业评审，学员及时收到反馈。

### 旅程 3：管理员 - 学期初配置系统（管理旅程）

**人物：王主任** - 培训机构管理员，新学期需要配置学科和学员

**理想旅程：**
1. **登录系统** → Dashboard 显示用户、学科统计
2. **批量导入学员** → 下载模板，填写信息，上传导入
3. **创建学科** → 配置基本信息和分组设置
4. **分配学员** → 批量添加学员到学科
5. **验证配置** → 检查各模块正常工作

**成功时刻：** 系统配置完成，教学工作顺利开展。

### 旅程 4：学员 - 小组协作提交（边缘场景）

**人物：小王** - 小组组长

**理想旅程：**
1. **创建小组** → 成为组长
2. **审批申请** → 批准组员加入
3. **协调作业** → 组内沟通
4. **代表提交** → 以小组身份提交
5. **查看反馈** → 全组共享评分

### 旅程能力映射

| 旅程 | 揭示的能力需求 |
|------|----------------|
| 学员-核心 | Dashboard、学科详情、课程查看、作业提交、通知接收 |
| 教员-核心 | 提交列表、代码查看、行级评论、评分功能、批量操作 |
| 管理员-配置 | 用户导入、学科创建、学员分配、系统监控 |
| 学员-小组 | 小组创建、申请审批、小组提交 |

## 9. 功能需求

### 用户认证与账户

- **FR1:** 用户可以使用用户名和密码登录系统
- **FR2:** 用户可以查看自己的个人信息
- **FR3:** 用户可以修改自己的密码
- **FR4:** 系统根据用户角色显示不同的功能菜单

### 仪表盘

- **FR5:** 管理员可以在 Dashboard 查看用户、学科、课程统计数据
- **FR6:** 教员可以在 Dashboard 查看待评审作业数量
- **FR7:** 学员可以在 Dashboard 查看今日课程、待提交作业、未读通知
- **FR8:** 所有用户登录后 Dashboard 正常加载，无 404 错误

### 学科管理

- **FR9:** 管理员可以创建学科，配置名称、描述、日期范围
- **FR10:** 管理员可以配置学科是否为分组学科及小组人数限制
- **FR11:** 管理员可以编辑和删除学科
- **FR12:** 管理员可以将学员添加到学科或从学科中移除
- **FR13:** 学员可以查看自己所属的学科列表
- **FR14:** 用户可以查看学科详情页，包含完整的课程列表

### 课程管理

- **FR15:** 教员/管理员可以在学科下创建课程
- **FR16:** 教员/管理员可以编辑课程内容、作业描述、截止时间
- **FR17:** 教员/管理员可以删除课程
- **FR18:** 用户可以查看课程详情，包含课程内容和作业要求
- **FR19:** 用户可以通过日历视图查看课程安排

### 作业提交

- **FR20:** 学员可以为课程提交作业文件（支持 ZIP/RAR）
- **FR21:** 学员可以重新提交作业
- **FR22:** 系统可以解压并展示提交文件的目录结构
- **FR23:** 教员可以查看学员提交列表和提交状态
- **FR24:** 教员可以查看提交的文件内容，支持代码语法高亮

### 评分与评论

- **FR25:** 教员可以为提交添加行级代码评论
- **FR26:** 教员可以编辑和删除自己的评论
- **FR27:** 教员可以为提交评分（A/B/C/D/E 等级）
- **FR28:** 教员可以为评分添加评语
- **FR29:** 教员可以修改已有的评分
- **FR30:** 学员可以查看自己提交的评分和评语
- **FR31:** 评分保存时系统响应正常，无 500 错误

### 小组协作

- **FR32:** 学员可以在分组学科中创建小组
- **FR33:** 学员可以申请加入已有小组
- **FR34:** 组长可以批准或拒绝加入申请
- **FR35:** 组长可以移除小组成员
- **FR36:** 组长可以解散小组
- **FR37:** 小组可以以小组身份提交作业

### 通知系统

- **FR38:** 系统在新课程发布时通知相关学员
- **FR39:** 系统在截止日期前提醒未提交的学员
- **FR40:** 系统在评分完成后通知学员
- **FR41:** 系统在小组申请和审批时发送通知
- **FR42:** 用户可以查看通知列表
- **FR43:** 用户可以标记通知为已读

### UI/UX 一致性

- **FR44:** 所有页面应用统一的全局主题样式
- **FR45:** 所有异步操作显示加载状态指示
- **FR46:** 所有错误场景显示用户友好的错误提示
- **FR47:** 所有表单提供一致的验证反馈

## 10. 非功能需求

### 性能

| NFR | 指标 | 目标值 |
|-----|------|--------|
| **NFR1** | 页面首次内容绘制 (FCP) | < 3 秒 |
| **NFR2** | API 响应时间（标准请求） | < 500ms |
| **NFR3** | 页面切换响应 | < 200ms |
| **NFR4** | 文件上传进度反馈 | 实时更新 |
| **NFR5** | 代码查看器渲染 | < 1 秒（1000 行以内） |

### 安全

| NFR | 要求 |
|-----|------|
| **NFR6** | 用户密码使用 BCrypt 加密存储 |
| **NFR7** | API 请求使用 JWT Token 认证 |
| **NFR8** | Token 有效期 24 小时，过期需重新登录 |
| **NFR9** | 角色权限在后端强制校验 |
| **NFR10** | 文件上传仅允许 ZIP/RAR 格式 |
| **NFR11** | API 请求限流：每 IP 每分钟 100 次 |
| **NFR12** | 响应头包含 XSS、点击劫持防护 |

### 可扩展性

| NFR | 要求 |
|-----|------|
| **NFR13** | 系统支持 30-100 并发用户 |
| **NFR14** | SQLite 数据库满足当前规模需求 |
| **NFR15** | 文件存储使用本地磁盘，按学科/课程组织 |

### 可访问性

| NFR | 要求 |
|-----|------|
| **NFR16** | 遵循 WCAG 2.1 AA 基础标准 |
| **NFR17** | 支持键盘导航 |
| **NFR18** | 表单错误提示清晰可见 |
| **NFR19** | 颜色对比度满足可读性要求 |

### 可靠性

| NFR | 要求 |
|-----|------|
| **NFR20** | 核心页面无 404 错误 |
| **NFR21** | 核心功能无 500 错误 |
| **NFR22** | 所有异常提供用户友好的错误信息 |
| **NFR23** | 数据操作使用乐观锁防止并发冲突 |
| **NFR24** | 数据删除使用逻辑删除，支持恢复 |

### 浏览器兼容性

| NFR | 要求 |
|-----|------|
| **NFR25** | 支持 Chrome 90+, Firefox 88+, Edge 90+, Safari 14+ |
| **NFR26** | 主要目标：桌面浏览器（1280px+） |
