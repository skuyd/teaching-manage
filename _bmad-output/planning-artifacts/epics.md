# Teaching Manage 系统完善 - Epic 分解

## 概览

本文档将 PRD 和架构文档中的需求分解为可实现的 Epic 和 Story。

## 需求清单

### 功能需求 (FR1-FR47)

#### 用户认证与账户 (FR1-FR4)
- **FR1:** 用户可以使用用户名和密码登录系统
- **FR2:** 用户可以查看自己的个人信息
- **FR3:** 用户可以修改自己的密码
- **FR4:** 系统根据用户角色显示不同的功能菜单

#### 仪表盘 (FR5-FR8)
- **FR5:** 管理员可以在 Dashboard 查看用户、学科、课程统计数据
- **FR6:** 教员可以在 Dashboard 查看待评审作业数量
- **FR7:** 学员可以在 Dashboard 查看今日课程、待提交作业、未读通知
- **FR8:** 🔴 所有用户登录后 Dashboard 正常加载，无 404 错误 [P0]

#### 学科管理 (FR9-FR14)
- **FR9:** 管理员可以创建学科，配置名称、描述、日期范围
- **FR10:** 管理员可以配置学科是否为分组学科及小组人数限制
- **FR11:** 管理员可以编辑和删除学科
- **FR12:** 管理员可以将学员添加到学科或从学科中移除
- **FR13:** 学员可以查看自己所属的学科列表
- **FR14:** 🔴 用户可以查看学科详情页，包含完整的课程列表 [P0]

#### 课程管理 (FR15-FR19)
- **FR15:** 教员/管理员可以在学科下创建课程
- **FR16:** 教员/管理员可以编辑课程内容、作业描述、截止时间
- **FR17:** 教员/管理员可以删除课程
- **FR18:** 用户可以查看课程详情，包含课程内容和作业要求
- **FR19:** 用户可以通过日历视图查看课程安排

#### 作业提交 (FR20-FR24)
- **FR20:** 学员可以为课程提交作业文件（支持 ZIP/RAR）
- **FR21:** 学员可以重新提交作业
- **FR22:** 系统可以解压并展示提交文件的目录结构
- **FR23:** 教员可以查看学员提交列表和提交状态
- **FR24:** 教员可以查看提交的文件内容，支持代码语法高亮

#### 评分与评论 (FR25-FR31)
- **FR25:** 教员可以为提交添加行级代码评论
- **FR26:** 教员可以编辑和删除自己的评论
- **FR27:** 教员可以为提交评分（A/B/C/D/E 等级）
- **FR28:** 教员可以为评分添加评语
- **FR29:** 教员可以修改已有的评分
- **FR30:** 学员可以查看自己提交的评分和评语
- **FR31:** 🔴 评分保存时系统响应正常，无 500 错误 [P0]

#### 小组协作 (FR32-FR37)
- **FR32:** 学员可以在分组学科中创建小组
- **FR33:** 学员可以申请加入已有小组
- **FR34:** 组长可以批准或拒绝加入申请
- **FR35:** 组长可以移除小组成员
- **FR36:** 组长可以解散小组
- **FR37:** 小组可以以小组身份提交作业

#### 通知系统 (FR38-FR43)
- **FR38:** 系统在新课程发布时通知相关学员
- **FR39:** 系统在截止日期前提醒未提交的学员
- **FR40:** 系统在评分完成后通知学员
- **FR41:** 系统在小组申请和审批时发送通知
- **FR42:** 用户可以查看通知列表
- **FR43:** 用户可以标记通知为已读

#### UI/UX 一致性 (FR44-FR47)
- **FR44:** 🟡 所有页面应用统一的全局主题样式 [P1]
- **FR45:** 🟡 所有异步操作显示加载状态指示 [P1]
- **FR46:** 🟡 所有错误场景显示用户友好的错误提示 [P1]
- **FR47:** 🟡 所有表单提供一致的验证反馈 [P1]

### 非功能需求 (NFR1-NFR26)

#### 性能 (NFR1-NFR5)
- **NFR1:** 页面首次内容绘制 (FCP) < 3 秒
- **NFR2:** API 响应时间（标准请求）< 500ms
- **NFR3:** 页面切换响应 < 200ms
- **NFR4:** 文件上传进度反馈实时更新
- **NFR5:** 代码查看器渲染 < 1 秒（1000 行以内）

#### 安全 (NFR6-NFR12)
- **NFR6:** 用户密码使用 BCrypt 加密存储
- **NFR7:** API 请求使用 JWT Token 认证
- **NFR8:** Token 有效期 24 小时，过期需重新登录
- **NFR9:** 角色权限在后端强制校验
- **NFR10:** 文件上传仅允许 ZIP/RAR 格式
- **NFR11:** API 请求限流：每 IP 每分钟 100 次
- **NFR12:** 响应头包含 XSS、点击劫持防护

#### 可扩展性 (NFR13-NFR15)
- **NFR13:** 系统支持 30-100 并发用户
- **NFR14:** SQLite 数据库满足当前规模需求
- **NFR15:** 文件存储使用本地磁盘，按学科/课程组织

#### 可访问性 (NFR16-NFR19)
- **NFR16:** 遵循 WCAG 2.1 AA 基础标准
- **NFR17:** 支持键盘导航
- **NFR18:** 表单错误提示清晰可见
- **NFR19:** 颜色对比度满足可读性要求

#### 可靠性 (NFR20-NFR24)
- **NFR20:** 核心页面无 404 错误
- **NFR21:** 核心功能无 500 错误
- **NFR22:** 所有异常提供用户友好的错误信息
- **NFR23:** 数据操作使用乐观锁防止并发冲突
- **NFR24:** 数据删除使用逻辑删除，支持恢复

#### 浏览器兼容性 (NFR25-NFR26)
- **NFR25:** 支持 Chrome 90+, Firefox 88+, Edge 90+, Safari 14+
- **NFR26:** 主要目标：桌面浏览器（1280px+）

### 架构额外需求

- **ARCH-1:** 增强 GlobalExceptionHandler 统一错误处理
- **ARCH-2:** 使用 CSS 变量实现全局主题
- **ARCH-3:** 前端添加 ErrorBoundary 组件
- **ARCH-4:** 增强日志用于调试

## Epic 1: 核心路径修复

修复阻断性问题，让三种角色（管理员/教员/学员）的核心流程可用。

### Story 1.1: 修复 Dashboard 404 错误

**As a** 用户（管理员/教员/学员），
**I want** 登录后 Dashboard 页面正常加载，
**So that** 我可以看到与角色相关的统计信息和待办事项。

**Acceptance Criteria:**

**Given** 用户已登录系统
**When** 路由跳转到 /dashboard
**Then** Dashboard 页面正常渲染，无 404 错误
**And** 管理员看到用户/学科/课程统计
**And** 教员看到待评审作业数量
**And** 学员看到今日课程、待提交作业、未读通知

**技术参考：** 检查 Vue Router 配置、组件路径、API 端点

---

### Story 1.2: 修复学科详情页显示

**As a** 学员，
**I want** 点击学科后能看到完整的学科详情和课程列表，
**So that** 我可以了解课程安排并准备学习。

**Acceptance Criteria:**

**Given** 学员已加入某学科
**When** 点击学科进入详情页
**Then** 页面正常加载学科信息（名称、描述、日期范围）
**And** 课程列表正确显示
**And** 可以通过日历或列表视图查看课程
**And** 无控制台错误

**技术参考：** 检查 SubjectDetail.vue、API 响应处理

---

### Story 1.3: 修复评分功能 500 错误

**As a** 教员，
**I want** 为学员提交评分时系统正常保存，
**So that** 我可以完成作业评审流程。

**Acceptance Criteria:**

**Given** 教员正在查看学员提交详情
**When** 选择评分等级（A/B/C/D）并添加评语后点击保存
**Then** 评分成功保存，无 500 错误
**And** 页面显示"评分成功"提示
**And** 刷新后评分数据正确显示
**And** 学员收到评分完成通知

**技术参考：** 检查 GradeForm.vue、API 响应拦截器解构模式

**状态：** ✅ 已修复（Axios 响应拦截器解构模式修正）

## Epic 2: UI 一致性改造

统一全局视觉体验，提升用户感知质量。

### Story 2.1: 实现全局 CSS 变量主题

**As a** 用户，
**I want** 所有页面使用统一的颜色、间距、字体，
**So that** 系统看起来专业一致。

**Acceptance Criteria:**

**Given** 用户访问系统任意页面
**When** 页面加载完成
**Then** 使用统一的 CSS 变量（--primary-color, --spacing-*, --font-*）
**And** 暗色主题样式统一（dark-page, dark-card, dark-table 类）
**And** 无页面出现明显的样式断层

**技术参考：** 创建 styles/variables.scss、更新现有页面

---

### Story 2.2: 标准化加载状态指示

**As a** 用户，
**I want** 所有异步操作显示清晰的加载状态，
**So that** 我知道系统正在处理我的请求。

**Acceptance Criteria:**

**Given** 用户触发异步操作（API 调用、文件上传等）
**When** 请求进行中
**Then** 显示 loading 状态（el-loading 或骨架屏）
**And** 操作完成后 loading 消失
**And** 按钮在请求期间禁用防止重复提交

---

### Story 2.3: 实现统一错误提示组件

**As a** 用户，
**I want** 所有错误场景显示友好的错误提示，
**So that** 我可以理解问题并采取行动。

**Acceptance Criteria:**

**Given** 发生任何错误（网络、验证、权限等）
**When** 错误被捕获
**Then** 显示用户友好的错误消息（非技术术语）
**And** 错误提示样式统一（使用 el-message 或 el-alert）
**And** 网络错误提示重试选项
**And** 控制台无未处理的错误

**技术参考：** 增强 GlobalExceptionHandler（后端）、ErrorBoundary（前端）

---

### Story 2.4: 统一表单验证反馈

**As a** 用户，
**I want** 所有表单提供一致的验证反馈，
**So that** 我可以快速修正输入错误。

**Acceptance Criteria:**

**Given** 用户提交表单
**When** 输入不符合验证规则
**Then** 显示内联验证错误（红色边框 + 错误文本）
**And** 首个错误字段自动聚焦
**And** 验证规则前后端一致
**And** 错误消息清晰说明问题和解决方法
